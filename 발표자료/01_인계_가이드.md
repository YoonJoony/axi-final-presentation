### 3.1 느낌과 금지
- 컨셉: **챕터 스토리형**. 악성코드를 잘 모르는 IT 기업 청중(과제 제공 기업 스피디 같은 곳)이 이야기로 따라오게 한다.
- **장마다 메시지 하나.** 글과 상자를 최소로 해서 **3초 안에 핵심이 읽혀야** 한다. 첫 시안(상자 20개짜리 아키텍처)은 "한 장에 글과 상자가 너무 많아 한눈에 안 보인다"는 이유로 버려졌다. 한 장에 꽉 차는 흐름은 2~3장으로 나눈다.
- **하지 않는 것:** 화려한 잡지풍, 입자 효과, 3D, **계속 반짝이거나 반복되는 효과**(모든 효과는 한 번만), 사진·영상 배경.

### 3.2 무대·글꼴·크기
- **1920×1080 고정 무대**를 통째로 화면에 맞춰 줄인다(frontend-slides 스킬의 viewport-base 방식). 위치는 모두 1920×1080 좌표.
- 글꼴: **SUIT Variable**(SIL OFL 1.1). 굵기 400·500·600·700·800.
- 크기: **제목 64~80px**(표지 80 · 두 줄 제목 72 · 한 줄 제목 64), **본문 28px 이상**. 28px 미만은 번호 배지 22~24, 영문·장 소제목 22, 태그·칩·출처·그림 설명 24, 표시줄 안 '실제/가정' 20, 재현 그림 안 장식 영문 20뿐.

### 6.4 저절로 맞춰지는 것 / 손으로 맞출 것
- **저절로**: 번호 배지, 왼쪽 탭, 총 장수(`[data-total]`), 지금 장 번호·이름, 진행 막대. 16장 이상이면 탭 간격이 좁아진다(`.rail.dense`).
- **손으로**: `data-story`·`data-arch`·`data-astep` 값, 카메라 위치(`data-offs`), 표시줄 글, 차트 값.

### 6.5 스크립트(`client.js`)
- `show(i)`: i장으로 이동(효과 다시 틀기, 숫자·차트·표시줄·카메라 맞추기, 주소 `#n`).
- `setArch(i, s, prev)`: 카메라. 앞으로 넘기면 아래에서 올라오고, 뒤로 넘기면 위에서 내려온다.
- `countUp`, `drawChart`, `toggleFs`(F 키와 ⛶ 버튼이 같은 함수), `fit`.

### 6.6 새 장 넣는 법
1. 비슷한 장의 `<section class="slide …">…</section>`을 통째로 복사해 원하는 자리에 붙인다(문서 순서 = 장 순서).
2. `data-label`과 글을 바꾼다. **배지 번호·탭·총 장수는 건드리지 않는다**(저절로).
3. 효과는 `.rv d1`~`d8`, 숫자는 `data-to`, 그림은 `.blur`, 막대는 `.fill`.
4. 출처: `<p class="src rv d6">출처 · 매체, YYYY.MM.DD</p>`.
5. 7절 검사로 문제 0과 사진을 확인한다.

두 줄 제목 장 뼈대:

```html
<section class="slide lay-split" data-label="탭 이름" aria-label="장 설명">
  <div class="txt">
    <div class="eyebrow rv d1"><span class="badge">00</span><span class="en">소제목</span><span class="tag real">실제 사례</span></div>

```

### 6.7 카메라 그림 고치는 법
- `#atrack`은 **가로 1600 × 세로 2700짜리 긴 그림**이다. 화면 위치 = (200 + x, 192 + y − 카메라 위치).
- `#atrack`의 `data-offs="0,524,1064,1820"` = `data-arch` 1·2·3·4일 때 카메라 위치. 보이는 창 높이는 776px이고 위아래 44~52px는 흐려진다.
- 요소마다 `data-lv="1 2"`처럼 **보이는 장 번호(data-arch 값)** 를 적는다. 두 장에 걸친 요소는 카메라가 움직여도 남아 이어지는 느낌을 준다.
- 요소: 상자 `.an`(`--cx` 가운데 x, `top`; 변형 `key`·`de`·`q`·`p`), 칩 `.ach d|w|p`(`top` = 가운데 y − 29), 글 `.al2`(`--x`, `c`면 가운데), 신호 알약 `.sig`, 선 `svg.alines` 안 `path.ln a|d|w|p|nm`, 줄 `path.lane d|p`.
- 손으로 계산하기 싫으면 `참고/생성기/build.mjs`의 `AN`·`CHIP`·`LB`·`LN`·`SIG` 함수와 `ARCH` 문자열을 본다.

### 6.8 생성기
- `참고/생성기/`는 기준본을 만든 원본이다. `node 발표자료/참고/생성기/build.mjs 출력.html` → 기준본과 똑같은 파일이 나온다(2026-11-23 확인).
- v01 이후는 **HTML 파일 하나를 직접 고치는 방식**을 권한다. 생성기와 HTML 직접 수정을 섞지 않는다.

### 7.4 이미 겪은 함정
1. **SUIT의 "→" 글자는 ">"처럼 보인다** — 화살표는 SVG(`.arw`).
2. 선 스타일을 `.alines path`처럼 넓게 걸면 화살촉(marker 안 path)이 사라진다 — `.alines > path`.
3. 가운데 맞춤은 CSS `translate`, 등장 효과는 `transform`으로 따로.
4. 브라우저 창이 가려지면 효과가 멈춘 채 사진이 찍힌다 — `check.mjs`는 헤드리스라 괜찮다.
5. 규칙 순서 충돌(`.ovs`가 `.sig`의 흰 글자를 덮음) → `.ovs.sig`로 다시 지정.
6. 글꼴이 늦게 오면 글 폭이 바뀐다 — 글꼴을 불러온 상태에서 검사.
